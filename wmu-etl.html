ETL & Data Warehouse Project

Western Midlands University (WMU) Student Information ETL & Data Warehouse

An end-to-end SSIS and SQL Server data engineering project designed to transform raw higher-education student data into a validated, auditable, and reporting-ready dimensional data warehouse.

SQL Server SSIS T-SQL ETL Data Warehouse Star Schema Data Quality Power BI Ready

Project Overview

Western Midlands University (WMU) is a fictional higher-education institution created for this project. The solution integrates student information from multiple CSV source files into a structured SQL Server reporting environment using SSIS.

The project implements staging, reference validation, exception handling, audit reporting, and a dimensional warehouse structure designed to support reliable institutional analytics and Power BI reporting.

ETL Architecture

The solution follows a controlled ETL process where source data first enters staging tables, passes through business-rule validation, and is either redirected to exception tables or loaded into the reporting warehouse. Audit tables provide visibility into validation outcomes and ETL execution.

Final ETL Results

Business Problem

Higher-education institutions often manage information across separate admissions, enrollment, academic, financial-aid, and student-engagement systems. Without a centralized and validated reporting environment, institutional reporting can suffer from duplicate records, invalid values, inconsistent definitions, weak audit visibility, and unreliable decision-making.

This project addresses that challenge by creating a centralized ETL pipeline and data warehouse that produces clean, validated, and reporting-ready student information.

ETL Process

1. Source & Staging

Student data from CSV source files is extracted and loaded into SQL Server staging tables.

2. Validation

SQL business rules and reference tables validate student, enrollment, academic, financial-aid, and attendance records.

3. Exception Handling

Records failing validation are redirected to dedicated exception tables instead of entering the warehouse.

4. Warehouse Loading

Clean validated records are loaded into dimensional and fact tables using a reporting-ready star-schema design.

5. Audit Reporting

Validation summaries and ETL execution results are logged for monitoring, reconciliation, and audit visibility.

6. Reporting

The resulting warehouse supports Power BI reporting for institutional analytics and decision-making.

Data Quality & Exception Handling

Data-quality controls were built directly into the ETL process. Validation rules identify issues including duplicate identifiers, invalid categories, incorrect GPA values, invalid credit-hour ranges, orphan student records, invalid attendance values, and other business-rule violations.

Controlled Validation

Reference tables and SQL rules enforce valid values before data enters the reporting warehouse.

Exception Tables

Invalid records are isolated with issue types and issue descriptions, making them available for review and correction.

Audit Transparency

Validation and ETL execution tables provide visibility into processed, valid, and invalid records.

Data Warehouse Design

The final reporting environment uses a dimensional warehouse centered around a student dimension. Fact tables capture enrollment, academic-performance, financial-aid, and student-attendance activity. Surrogate student keys support consistent relationships between the dimension and fact tables.

DimStudent

Stores student profile information including demographics, program, department, level, admission date, and status.

FactEnrollment

Stores enrollment activity including term, enrollment status, credit hours, residency status, and campus.

FactAcademicPerformance

Stores grades, credit hours, term GPA, cumulative GPA, and academic-standing information.

FactFinancialAid

Captures aid type, amount, FAFSA status, and financial-aid status.

FactStudentAttendance

Captures attendance, LMS activity, advisor meetings, and student engagement-risk measures.
